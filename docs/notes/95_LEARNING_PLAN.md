## שלב 0: התמונה הגדולה (שעה–שעתיים, בלי קוד)

**המטרה:** לדעת מה כל חלק עושה, לפני שנכנסים לאף קובץ.

- **הספר, 4.9 ואיור 10:** הצינור של שאלה. ‏**ו-3.1.6:** למה המודל כותב תוכנית ולא SQL.
- **`docs/notes/30_ARCHITECTURE.md`,** ו-**`CLAUDE.md`** עד סעיף "Commands".
- **המאמר של Anthropic, "Building effective agents".** המערכת שלנו היא **workflow, ולא agent:** הקוד קובע את המסלול, והמודל ממלא צעדים מוגדרים. בשפה של המאמר:

| הדפוס במאמר | אצלנו |
|---|---|
| Prompt chaining עם gate בקוד | השכתוב, אחריו intent, אחריו המהדר, ואז השליפה, הסינתזה והשער. בין כל שניים יש בדיקה בקוד |
| Routing | ה-disposition של intent: תשובה, הפניה לחקירה, בירור או פעולה. והסיווג הבלתי תלוי (C) |
| Parallelization (sectioning) | ‏C רץ במקביל לשליפה. ובמשימה 2: תוכנית לכל קריאה, במקביל |
| Evaluator | השער (support scoring) ובדיקת הכיסוי (B). ההבדל: אצלנו הם **מסננים,** ולא נותנים משוב בלולאה |
| ACI ו-poka-yoke | הסכמות, המהדר שדוחה תוכנית לא תקינה, והפניות סמליות במקום ערכים |

**בדיקה עצמית:** למה המודל לא כותב SQL? איפה בצינור מוכנסת ההרשאה? מה ההבדל בין workflow ל-agent, ולמה בחרנו ב-workflow?

## מילון קצר

| מונח | מה זה |
|---|---|
| **reading (קריאה)** | שליפה אחת מתוך תוכנית: SELECT, ‏FROM, ‏WHERE, ‏GROUP_BY. לכל קריאה יש `label` |
| **plan (תוכנית)** | מה ש-intent מחזיר: disposition, קריאות, עמימות, ‏`unresolved` |
| **alias** | שם של עמודה בתוך קריאה. ההפניות במשפט הן `{label.alias#row}` |
| **disposition** | מה עושים עם השאלה: answer, ‏refer (הפניה לחקירה), ‏needs_clarification, או פעולה |
| **Examined** | שורה שהקוד כותב: מה באמת נבדק. השקיפות של המערכת |
| **gate (שער)** | בדיקה שכל משפט נתמך ברשומות |
| **golden** | פלט שמור, שמושווה תו בתו |
| **scripted model** | מודל מזויף שמחזיר תשובות קבועות, לדמו ולבדיקות |
| **dry_run** | תמחור סבב בלי מודל |
| **replay** | ניגון של תשובות מודל מוקלטות, ב-0$ |
