# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

MedAgentPro is an LLM-driven root-cause-analysis pipeline, developed as a project book in phases. Phase A (feasibility studies) is complete and lives under `studies/`. Phase B (the actual application) is starting: the query assistance (chat) pipeline core and the engine pieces are in `backend/`, the rest of `backend/` and `frontend/` are skeletons.

The top-level `README.md` is empty; the study READMEs and `studies/PROVENANCE.md` are the real documentation.

## Layout and state

- **`backend/`** — FastAPI service. Run everything from `backend/` (`pytest.ini` puts it on `pythonpath`, so packages import as `query_assistance`, `shared`, ...). `main.py`, `api/`, `reasoning/`, `tools/` and the other `shared/` modules are still **empty**. What holds code, copied from `project filles/03_Code` (that folder is the original and is left in place):
  - `query_assistance/` — the chat pipeline (book 4.9). `compiler.py` validates the schema 1 plan, injects entitlement and LIMIT, checks identifier provenance (NFR 27) and builds parameterised SQLite queries. `gate.py` checks the gate output (schema 4). `prompts.py` loads and fills `templates/*.md` (rewrite, intent analysis, gate) and reduces history in three layers. `schema.json` and `relations.json` are **placeholders** until the company data structure arrives. `medagentpro_schemas.json` holds all JSON Schemas (Draft 2020-12); `summarization` and `synthesis` are `blocked`.
  - `model_client/client.py` — `ModelGateway`, `ScriptedModelGateway` (tests), `LiteLLMGateway` (imports `litellm` lazily, not yet in requirements).
  - `shared/circuit_breaker.py` — one breaker per dependency, shared state store.
  - `persistence/audit_repository.py` — `AuditRepository.write_event`, the single write path, HMAC chain per investigation.
  - `tests/` — pytest: `query_assistance/` (compiler, prompts, schema conformance) and `engine/` (breaker, gateway, audit). All model calls in tests go through `ScriptedModelGateway`.
- **`frontend/`** — Next.js 16 / React 19 / Tailwind 4 app (default scaffold). `frontend/AGENTS.md` (pulled in by `frontend/CLAUDE.md`) warns that this Next.js version has breaking changes versus training data: read the relevant guide in `frontend/node_modules/next/dist/docs/` before writing frontend code. That block is regenerated by `next dev`.
- **`studies/`** — Phase A feasibility studies reported in sections 3.2 and 3.3 of the project book.

Studies (run from inside the study directory — scripts use relative paths like `samples/`, `results/`):

```bash
# Model-calling runs (need ANTHROPIC_API_KEY; PowerShell: $env:ANTHROPIC_API_KEY="...")
python run_study.py                       # 3.2: options --only LOG-01, --conditions baseline|schema, --repeat N, --out DIR
python run_study.py --repeat 5            # 3.3: options --only, --conditions conversational|structured|calibrated|exemplified, --evidence FILE, --out DIR

# Offline analysis over retained results (no API key, no model call)
python verify_counts.py                   # 3.2, produces Table 8
python analyze_references.py              # 3.3, cited-identifier counts (--no-ranges to skip expanding E8-E18 spans)
```

## Studies: rules that matter

- **Results are an evidentiary record.** `studies/PROVENANCE.md` maps every number/figure in the book to a file and the command that reproduces it. Do not modify or delete anything under `results*/` directories, including superseded runs (`results-run1`, `results-fill-log06-invalid-facts`, etc.) — they are retained deliberately. Write new runs to a new `--out` directory.
- **Don't re-run model-calling scripts casually**: they cost API calls and write into `results/` by default, overwriting the primary record.
- Study scripts pin `MODEL = "claude-sonnet-4-5-20250929"`, temperature 0, and fixed prompts; every `results.json` records the model, temperature, output limit and full prompt text. Changing a prompt or setting invalidates comparison with the recorded runs.
- In 3.2, `facts.json` is the fact list in force; `facts-v1.json` is the older list used by superseded runs. Facts are fixed before any run.
- In 3.3, `evidence.json` holds the 3.2 structured summaries with elements labelled `E1`…`En`; `evidence_weak.json` / `evidence_calib.json` belong to unreported calibration runs.

## Gotchas

- `studies/3.2-ingestion/requirements.txt` is **UTF-16 LE with CRLF** (produced by PowerShell redirection). pip reads it, but grep/sed and some editors won't. `backend/requirements.txt` was converted to UTF-8; when regenerating it from PowerShell use `pip freeze | Out-File -Encoding utf8`.
- `jsonschema` must be 4.x (`Draft202012Validator`); 3.x imports fail.
- The study scripts use the Anthropic SDK while the backend dependencies list the `openai` SDK; the backend's model provider is not yet settled in code.
